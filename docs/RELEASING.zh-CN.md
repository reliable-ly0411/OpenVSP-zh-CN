# 发布与分支规范

## 版本与来源

- 发布版本遵循 [SemVer 2.0.0](https://semver.org/lang/zh-CN/)。先定义 API、宿主/SDK ABI、命令或文件格式的兼容性边界，再决定主、次、修订版本递增。
- 固定本仓的标签前缀、预发布序列及版本文件映射。预发布使用有序标识，例如 `-rc.1`；`v` 仅为标签前缀；构建元数据不参与优先级比较，不能用改哈希替代版本递增。
- 上游版本、包管理器版本和本仓发布版本须分别记录，准确说明真实基线。不要伪造上游身份、宿主版本或二进制兼容性。
- 发布后不移动标签，不覆盖或删除既有附件以替换版本；修复用新版本。历史链接需要变化时单独列影响并取得授权，不绕过不可变保护。

## 分支与历史

- 保留稳定线和开发线；专项改动通过 `feat/`、`fix/`、`ci/`、`docs/` 等独立主题分支进入实际维护线。现有仓库命名和主版本隔离见下方映射。
- 纯上游镜像维持上游历史和命名，不混入本地规范或汉化改动。保留有意义的提交及真实上游祖先；普通 merge，不 squash、不强推、不改写公开历史。
- 不因整理而删除未合入、未证明等价替代的改动。删除分支须有适用授权和恢复依据。

## 包与附件

- 有上游时，输出清单与包名结构应接近对应上游；多版本或多架构可按实际需要扩展。汉化产物在上游风格中添加 `-zh-CN`，不添加 `Codex-AI` 过程标识；非汉化插件不强加语言标识。
- 架构、操作系统、最低系统版本、Python/SDK ABI 必须真实，未验兼容性不得冒称。
- 下载附件保留成果和必要校验清单，最多额外一个简介文本。构建记录、截图、过程日志和交接材料放包内、源码技术文档或 CI 工件，不堆进 Release 下载区。
- 校验清单必须匹配实际文件名、字节数和 SHA-256；手工源码包须与 GitHub 自动 Source code ZIP/TAR 区分。

## 正文与公开沟通

- 同仓库各版本的标题、章节和包名保持相近风格。
- Release 正文保留对应上游发布说明全文，并给来源链接和版本；然后补本分支差异、安装、兼容性、已知限制、验证范围及校验信息。不能只给上游链接。无对应上游 Release 时明确说明，不编造说明。
- 若采用上游发布后的快照，分别列上游发布基线和新增提交，避免以基础版本号掩盖开发快照。
- 上游没有 GitHub Release 时核对官网公告或源仓 CHANGELOG 对应章节。全文转载必须符合上游许可；未获转载权时明确报告阻碍，不把链接或摘要冒称全文。软件修改与再分发许可需独立核验。
- 公开说明只写客观项目事实。去除 AI 完成用户任务、私人审批、内部交接或与复现无关的私人操作过程；产品本身涉及 Codex/AI 的技术名称正常保留。
- Issue 只在原验收范围和精确证据相符时关闭；部分解决需列剩余项。

## 发布检查

1. 核对基线、许可证、标签、软件内嵌版本、包管理器版本和下载名的映射。
2. 独立主题提交、轻量文档检查或相关代码测试、审阅、普通合并；分别记录通过、失败、跳过和未运行。
3. 固定源码和构建流程提交，验收最终原包，不以临时包结果冒充最终包，也不在验收后悄悄重建。
4. 正确设置正式/预发布和 Latest；开发 SDK 不替换稳定版 Latest。
5. 发布后重新下载校验附件，并确认旧标签/附件未变。无法验证的项目如实保留为限制。

通过普通 merge 进入本族开发线。只将最新 3.55.0 产品历史合回 main，不把旧版整库混入新版本。

### 五平台下载名映射

对照 [官方当前下载页](https://openvsp.org/download.php) 和
[官方旧版下载页](https://openvsp.org/download_old.php) 的拼写风格，当前新包如下：

| 实际目标 | 下载文件名（<版本> 为上表软件版本） | 边界 |
|---|---|---|
| Ubuntu 24.04 AMD64 | `OpenVSP-<版本>-Ubuntu-24.04_amd64-zh-CN.zip` | 保留官方 Ubuntu 拼写；本仓使用 ZIP |
| Ubuntu 24.04 ARM64 | `OpenVSP-<版本>-Ubuntu-24.04_arm64-Python3.12-zh-CN.zip` | 本仓新增原生目标，不称官方预编译包 |
| Windows x64 | `OpenVSP-<版本>-win64-Python3.11-zh-CN.zip` | Python 3.11 |
| macOS ARM64 | `OpenVSP-<版本>-macos-14-ARM64-Python3.11-zh-CN.zip` | 实际最低系统与运行证据必须满足 macOS 14 |
| macOS Intel x86_64 | `OpenVSP-<版本>-macos-15-intel-X64-Python3.11-zh-CN.zip` | 本仓实际构建目标为 macOS 15，不冒称更低系统兼容 |

Linux Python 为 3.12，Windows/macOS 为 3.11；NumPy 1.26.4、依赖约束 `<2`。
2026-10-20 对应官方旧版清单确认：Windows 和 Intel Mac 的 Python 3.11 包采用上述结构；
官方 Ubuntu AMD64 为 `.deb`，本仓改用便携 ZIP。官方 3.55.0/3.54.0 的 ARM64 Mac 包名为
`macos-15-ARM64-Python3.11`，本仓实际使用 macOS 14 原生目标；其余三族官方 ARM64 包名为
`macos-14-ARM64-Python3.11`。这些差异必须在 Release 正文写明，不仅添加语言后缀而冒称同一产物。
同一软件版本的不同 rc 可能采用相同 ZIP 基名，下载 URL 由精确标签区分，必须分目录保存，
并只配对同一 Release 的 `SHA256SUMS.txt`。发布资产仅五个 ZIP 和这一份完整清单；
至多再加一个简介文本。源码自动下载入口由 GitHub 提供，不冒充已测试的二进制包。
标题统一为 `OpenVSP <版本> 简体中文版（RC N）`，`prerelease=true`、`make_latest=false`。

### 上游说明与本地差异

官方 GitHub 仓库截至 2026-10-20 没有 Release 条目，但官网公告和源仓 `CHANGELOG.md` 有版本说明。
发布正文应完整保留精确官方标签的 `CHANGELOG.md` 对应版本章节，附固定提交链接及官网公告来源，
明确这是上游作者原文。该文档随上游源码按 [NOSA 1.3](../LICENSE) 提供，转载保留归属、许可、警告和链接。
原文涉及开发工具或 AI 的叙述属于上游历史，不删改、不转写成汉化维护者自己的成果声明。
已审全文与固定来源元数据保存在 `docs/upstream-release-notes/`；
`scripts/upstream_release_notes.py` 校验版本、来源提交、许可链接和完整字节哈希，
`scripts/native_release.py` 生成正文，相关正反例在晋级前执行。
若源码包含官方标签之后的上游改动，单列精确提交差异；本地修复另列，不混入上游引文。

本仓正文补充：本族本次变化、安装及校验方式、Python ABI、macOS 签名/公证状态、
已完成的原生检查与实际 GUI 平台、未验范围、社区模型许可缺口、精确源码与技术报告链接。
Linux GUI 抽查不能替代 Windows/macOS/ARM GUI 验收；旧 rc 的通过记录不能充当新包证据。
发布直接晋级已验原包；任何正文纠错与新包发布都不得移动历史标签或改变旧附件字节。

### 平台锁定与本仓维护规则

2026-10-20 核实：仓库级 `Enable release immutability` 已关闭，汉化标签的禁止改指向/删除
保护仍保留，允许创建新标签。已经锁定的 `3.55.0-zh-CN.rc.1` 仍显示 `immutable=true`；
关闭仓库开关不会将其解锁，不通过删除、重建或移动标签绕过保护。
新 rc 不要求 `immutable=true`，验收报告记录实际平台字段，不能把关闭状态写成已实施全局锁定。
本仓发布程序仍拒绝覆盖旧标签和附件，并保留同族祖先、完整哈希清单、原包晋级及远程读回门禁。

旧版说明补充优先使用[固定版本全文索引](upstream-release-notes/README.md)及普通文档 PR；
该操作不会自动修改旧 Release 页面、标签或附件。需要修改旧页面时另按明确目标和当前平台状态核验。
